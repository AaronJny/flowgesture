# Verification without connecting a personal Mac

Research: 2026-11-09. This workflow does not require connecting a personal computer. Cloud work can continue independently; the optional local check below is not a prerequisite. No third-party program was installed or run, and no system preferences or security settings were changed for this research.

## What public evidence actually supplies

**No complete, provenance-verified physical Spaces-swipe trace was found in the sources inspected below.** This is a scoped search result, not a claim that no such recording exists. Search covered the named repositories' indexed code, relevant original issues/comments, and linked source files using terms including `trace`, `recorded`, `capture`, `senderID`, and the private field names. GitHub directory views and a linked FasterSwiper serialization gist were unavailable through the research browser, so neither was treated as inspected evidence.

- **Reusable external fixture, wrong gesture family:** WebKit's [`SharedEventStreamsMac.mm`](https://github.com/WebKit/WebKit/blob/f310728c7012151f30108f04e7d56101bf0ac05d/Tools/TestRunnerShared/EventSerialization/mac/SharedEventStreamsMac.mm) contains timed begin/complete browser-back swipe arrays. They interleave class 29/HID 6 with public scroll class 22 and series markers 61/62. The completion fixture places gesture end at 121 ms and scroll end at 139 ms. These are valuable negative/pass-through cases, **not** class 30/HID 23 Spaces captures. The file supplies no capture OS/build, physical device, matching MT registry identity, or proof of physical provenance. Its Apple 2016 two-clause BSD header permits reuse with the copyright, conditions and disclaimer retained. If imported, preserve that notice and label the data “upstream test fixture, capture provenance unverified,” never “recorded native Spaces swipe.” The two arrays are now retained in `Tests/FlowGestureAppTests/Fixtures/WebKitBrowserBack/browser-back.json`, together with the original BSD notice. The test replays the classification fields without posting events; all other original field/value data remains in the fixture.
- **Definitions are not traces:** WebKit's [SPI header](https://github.com/WebKit/WebKit/blob/f310728c7012151f30108f04e7d56101bf0ac05d/Tools/TestRunnerShared/spi/CoreGraphicsTestSPI.h) corroborates private field identifiers. Its [serializer](https://github.com/WebKit/WebKit/blob/f310728c7012151f30108f04e7d56101bf0ac05d/Tools/TestRunnerShared/EventSerialization/mac/EventSerializerMac.mm) has a selected field list and omits values matching a plain event. A deserialized test event must not be mistaken for a complete, original hardware packet.
- **Recorder source, not recorded data:** FasterSwiper publishes [`record-gesture.cc`](https://github.com/mgbowen/FasterSwiper/blob/3665350bbd05cb7245063ade5143f155d8228d27/src/tools/record-gesture.cc) and other recording tools. The inspected recorder selects class 30/HID 23, skips PID-zero events, and exports selected fields without sender identity. That tool's existence is not a usable physical trace or a suitable unchanged capture procedure for this investigation. The project has an [Apache-2.0 license](https://github.com/mgbowen/FasterSwiper/blob/3665350bbd05cb7245063ade5143f155d8228d27/LICENSE); no recorded dataset with a verified capture manifest was located in the searched results.
- **Physical outcome reports, not replayable streams:** strafe [issue #3](https://github.com/rileycx/strafe/issues/3) reports swallowed real swipes and failed synthetic switching on macOS 27.0/26A428; the [maintainer follow-up](https://github.com/rileycx/strafe/issues/3#issuecomment-5714254894) reports a v0.1.1 fix and live testing. [Issue #17](https://github.com/rileycx/strafe/issues/17) reports opposite synthetic direction on 27.0.1/26A434. These motivate exact-build acceptance and edge tests, but contain no complete sender-correlated input stream. Link/summarize issue reports; do not assume a repository license covers every attachment or commenter contribution.

## Identity and terminal behavior remain empirical gates

Apple's [`IOHIDEventService.cpp`](https://github.com/apple-oss-distributions/IOHIDFamily/blob/777ccd9698845aadf711e32d843c8c9b777431d9/IOHIDFamily/IOHIDEventService.cpp) sets an event sender to the service's registry-entry ID. This supports that identity namespace, not retention of that identity through WindowServer/Dock transformation or equality with an MT device ID. No inspected trace pairs a derived Dock event with the originating MT service.

**PID zero is not established proof of physical origin.** strafe's [interceptor](https://github.com/rileycx/strafe/blob/42f69de6007348f7da0f5cba8c5b3ec534f18da2/Sources/strafe/SwipeInterceptor.swift#L183-L188) assumes that distinction. InstantSpaceSwitcher's [source](https://github.com/jurplel/InstantSpaceSwitcher/blob/2b883a995d1c81fbc6d75704372a6a0b546bb1ff/Sources/ISS/ISS.c) instead says its macOS 27 synthetic events re-enter with PID zero. Cyclist's [pinned recognizer](https://github.com/pszypowicz/cyclist/blob/cc9d5db2c89a60f86cd89726da9bf145654d46c7/Sources/Cyclist/DockSwipeRecognizer.swift#L54-L57) checks its own event-source tag, not PID zero. The Cyclist author separately [reports tag loss after deserialization](https://github.com/jurplel/InstantSpaceSwitcher/issues/72#issuecomment-5774014316). These differing implementations/reports require verification of the complete posting/tap path; none is a universal classifier contract.

Terminal protocols also differ: [Cyclist consumes qualified ended/cancelled events](https://github.com/pszypowicz/cyclist/blob/cc9d5db2c89a60f86cd89726da9bf145654d46c7/Sources/Cyclist/DockSwipeRecognizer.swift#L74-L90), whereas [strafe sometimes forwards a zero-motion real end after synthetic replacement, or an uncommitted original end](https://github.com/rileycx/strafe/blob/42f69de6007348f7da0f5cba8c5b3ec534f18da2/Sources/strafe/SwipeInterceptor.swift#L228-L264). That source behavior cannot establish that FlowGesture's consumption-only model leaves Dock idle. A video or action-count log alone cannot establish this either.

## Useful cloud and CI work

1. Keep native interception inactive. Use deterministic sequence replay and assertions for no late claim, immutable eligibility, at-most-one action, cancellation, unknown fields, sender loss/change, companions, and interruption quarantine. Artificial fixtures must say `synthetic`; external fixtures must retain source revision, license and provenance limits.
2. Treat WebKit's browser-back stream as a negative case: all events must remain pass-through. Never insert fabricated sender IDs or convert HID 6 to HID 23 to make it a “real” positive test.
3. Run the final revision's core tests, native bridge/decoder checks, UI smoke tests and package verification on macOS CI, with architecture/OS coverage where available. Record the exact commit and distinguish jobs actually passed from jobs only configured. These prove software behavior under supplied inputs, not physical suppression.
4. Reject incomplete future capture manifests. Positive hardware evidence needs exact OS build and binary revision, tap location/mask, physical device/transport, unmodified event ordering including companions and terminal, independently matched registry identity, raw all-up boundaries, dropped-record counts, native outcome and normal-input checks. Replay can expose model defects; even genuine captured-input replay cannot prove how Dock reacts when events are removed.

No exact-build suppression profile should be enabled from source inspection, synthetic tests, hosted CI or the optional diagnostics below. See [the existing hardware acceptance gates](gesture-arbitration-research.md#5-physical-machine-validation-plan-and-acceptance-gates).

## Optional self-run baseline, no remote access or source build

Only if useful to the user, use an **already installed and trusted** FlowGesture copy with the Diagnostics controls. This is not a request to install another tool, grant new permissions, bypass Gatekeeper, or alter system gesture assignments. If the controls or existing permissions are unavailable, skip it and continue cloud work.

1. Note the app version, macOS version/build, trackpad kind/connection, and current native horizontal assignment. Use no sensitive document; avoid testing destructive, script, messaging or purchase actions. An existing safe, visible rule is enough; otherwise skip the action comparison.
2. With FlowGesture paused, perform one left/right native swipe to note the baseline. Re-enable only the intended safe rules. Try one slow swipe and one short flick each way, observing the custom outcome and native Space movement separately. Existing builds may run both; this is baseline evidence, not a failed promise of suppression. Stop if input or animation gets stuck.
3. If the installed build has it, open **Diagnostics → Gesture diagnostics → Start recording**. Do one or two gestures, then **Stop recording → Export local trace…** immediately. Use separate short runs rather than filling the 512-record ring. Export before starting again, because a successful new start replaces the prior trace. No upload is automatic; sharing is optional.
4. A useful report is: app/version and OS build; gesture/device; attempts; custom action count; whether native movement also occurred; any missing normal input; optional local JSON. Keep any export private unless choosing to share it. Pause or quit afterward if desired.

The [actual UI](../../Sources/FlowGestureApp/SettingsView.swift), [local save action](../../Sources/FlowGestureApp/AppModel.swift) and [observer](../../Sources/FlowGestureApp/GestureDiagnostics.swift) support these controls. Capture is listen-only, capped at 60 seconds, and requires the engine running plus existing Input Monitoring access. Unknown events contain only receipt time/raw type; public scroll events can add public phases/sender ID, while touch records use a separate device-ID namespace. Recognition labels are not action-completion records. Receipt times include main-queue delivery, not hardware acquisition. Check `droppedRecords`; even zero drops does not establish complete event visibility. These exports cannot validate private Dock phases, native sender correlation, suppression timing or terminal recovery.
